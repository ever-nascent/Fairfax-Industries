## LFG system (`/lfg`)

| Rule | Decision |
|------|----------|
| Who can run it | Anyone |
| Modes | Standard, Street Brawl, Ranked |
| Ranked rank | Taken from the runner's **rank role** (can't claim a rank you don't have) |
| Ping | Standard → @LFG Standard · Street Brawl → @LFG Street Brawl · Ranked → only @LFG <that rank> |
| Post | Embed in the region's channel (`#lfg-na`, `#lfg-sa`, `#lfg-eu`, `#lfg-ru`, `#lfg-asia`, `#lfg-oce`, `#lfg-africa`; `/lfg` posts in the one it is run in): mentions the runner, links the voice lobby |
| Voice lobby | Created in "LFG Lobbies" category, deleted after 5 min empty, stays while occupied |
| Ranked lock | Only runner's rank ±1 can join (Deadlock's duo rule). **Eternus: Eternus only** (game rule) |
| Ranked size | No limit (friends can hang out) |
| Spam guard | One open lobby per person |
| Roles created by the bot | 11 rank roles, LFG Standard, LFG Street Brawl, 11 LFG <rank> roles |

### `/lfg-config` (staff = anyone with **Manage Channels**)

| Subcommand | Does |
|------------|------|
| `close lobby [reason]` | Closes a lobby now, even if occupied; reason goes to the server audit log |
| `timeout minutes` | Empty-lobby delete time, 1–120 min (default 5) |
| `lobby-category category` | Where the voice lobbies are created (posts go in the region channel `/lfg` was run in) |
| `mode mode enabled` | Turn Standard / Street Brawl / Ranked on or off |
| `show` | Current settings |

When a lobby closes for any reason (empty timeout, staff close, deleted by hand) its #lfg post is deleted.

Not enforceable by roles: Eternus' "within 3 subranks" rule (subranks aren't tracked).

## Soul Bag (decided + built Oct 10, 2026; awaiting his Discord check)

Named after the game's Soul Bag (the haunted souls a dead player drops). His calls, Oct 10:

## Hero Farming (built Oct 1-2, 2026; awaiting his Discord check)

The entries below are in the order the decisions were made, so later ones replace earlier ones where they differ (items were first stat-only, the roam was first one fight, `/farm` was first one command). The current state is summarised in `CLAUDE.md` ("Bot features").

His idea: pick a hero, use its in-game weapon, abilities and stats from the wiki, buy items for it, and it farms souls for you while you're away; you collect. Maybe more interactive later (buy items, corrupt them, adjust stats; a single-player PvE take on the game).

Decided (Oct 1):
- **Idle first.** Send the hero out, collect later. Interactive runs may come later on the same hero/item system.
- **Real stats, simplified fights.** Real hero base stats, weapon damage/fire rate and item bonuses from the wiki; fights resolved with a simple model, no full ability simulation.
- **About 5 heroes at launch** with different playstyles, then add the rest.
- **Earns real souls**, with a daily cap so it doesn't break the casino/Shop balance.

- **Stats come from the Deadlock wiki** (his call, Oct 1): its raw JSON pages `Data:HeroData.json` (hero + weapon stats, level/spirit scaling), `Data:ItemData.json` / `Data:ItemCards.json` (items) and `Data:AbilityData.json`.
- **Starter 5 (his pick, Oct 1):** Mina, Haze, Celeste, Paige, Abrams.
- Step 1 done: `npm run farm-data` saves their stats to `assets/farm/heroes.json`. Note: Baba, Deadman Danny, Nurse Harrow, Rat King, Solomon and Violet have placeholder stats on the wiki right now, so don't rely on them yet.

- **Abilities are the part with per-character logic; items are stat modifiers only** (his call, Oct 1; there are 156 shop items, 44 with actives, the rest passive). Item actives/procs are not modelled for now (they only give their flat stats); revisit if wanted. Abilities need real logic because they "do things".
- **Built Oct 1 (no Discord surface yet, tested by `node --test`): `src/utils/farm/`.** `ability.js` base class (wiki numbers + upgrade tiers + spirit scaling; hooks `want`, `cast`, `tick`, `on`), `engine.js` (0.1 s fight steps; all damage/heal/status goes through `Fight`), `stats.js` (wiki hero stats + boons + item stats), `hero.js` (builds a hero, loads `heroes/<hero>.js`). Haze is the reference implementation (`heroes/haze.js`); Mina, Celeste, Paige and Abrams still need their files (until then they fight with their gun only). `npm run farm-data` also saves `assets/farm/abilities.json` + `items.json`.
- Assumptions to check: Fixation's "0.2 / stack" is read as a percent; headshots aren't modelled; SpiritScaling on hero stats (e.g. Haze's clip) isn't applied; Smoke Bomb's 2nd charge isn't modelled; level boons use the wiki's LevelScaling per boon.

- **Farm targets and timings (his calls, Oct 1; now built, see "Command split" below).** No daily cap: the limits are per-member cooldowns, and dying (a failed attempt leaves the target at full health, nothing paid). Cooldowns: **Tier 1 camp 1 h, Tier 2 camp 3 h, Tier 3 camp 6 h, Guardian 4 h, Walker 8 h, the base siege once a day.** **`/jungle roam`**: every 30 minutes, a random Crate ("boxes") or Sinner's Sacrifice. Mid-Boss: repeatable, once every 12 hours (his call, Oct 2). This replaces the earlier "one time only" idea for Guardian/Walker (they are on cooldowns now).
- **Base siege (his design):** one continuous run, Base Guardians, then both Shrines, then the Patron (and the weakened Patron), health carried through; if the hero dies it all restarts. Incredibly hard on purpose. Wiki facts used: Shrines can't be hurt until a pair of Base Guardians is down, they "attack" with the Patron's beam (440 + 5% of max health per second), the second Shrine has 10,000 HP (first 5,000), the Patron can't be hurt until both Shrines are down, and base structures have extra bullet resist that shrinks with each hero nearby (solo here). Souls: Base Guardians 1,000 each, Shrines 2,000 each, Patron 0 (paid only on clearing everything).
- **Rejuv (his clarification):** the Mid-Boss doesn't revive anyone during the fight; a hero who dies against it stays dead. **Killing it drops a Rejuv** the member keeps, which later lets the hero get back up once (full health after 3 s) mid-fight, e.g. in the siege. Separate from the Shop's Rejuv for `/urn` streaks. Not decided: how many a kill gives (1 placeholder), whether they expire, where they're stored.
- **Wiki data per target** (all `Data:NpcData.json`, souls from GenericData): camps = `neutral_*_weak/normal/strong` (129 / 322 / 1133 HP; 41 / 68 / 181 souls per creep; Tier 1/2/3 = small/medium/large, camp makeups: 3 small / 2 medium + 3 small / 3 large), Guardian `npc_boss_tier1` (5500 HP, 1,375 souls), Walker `npc_boss_tier2` (6000 HP, 3,675), Mid-Boss `npc_super_neutral` (13000 HP, 15 HP/s regen, 3,000), Sinner's Sacrifice (500 HP, 155), Crate (23 souls, 60% drop, health not on the wiki).

Not discussed with him yet: whether he wants a flat scale or his own amounts per target.
